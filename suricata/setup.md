# Suricata Setup

## Objective

Deploy Suricata on pfSense to monitor LAB-LAN traffic and forward structured IDS events to Wazuh.

Suricata is used as the network intrusion detection component of the homelab.

## Placement

Suricata runs directly on pfSense.

```text
pfSense LAN IP: 10.10.10.1
Monitored interface: hn1
Network: 10.10.10.0/24
Mode: IDS
Blocking: disabled
```

The purpose of the V1 is detection and visibility, not automatic blocking.

## Version

The Suricata version used during the V1 validation is:

```text
Suricata 8.0.5 RELEASE
```

## Rules

ET Open rules are installed and enabled.

Relevant rule categories include:

- scan detection;
- policy detection;
- web-related activity;
- protocol anomalies;
- reconnaissance traffic.

One validated detection used:

```text
Signature: ET SCAN Possible Nmap User-Agent Observed
Signature ID: 2024364
Severity: 1
Category: Web Application Attack
```

The active EVE file is:

```text

```

The active Suricata configuration file is:

```text
/usr/local/etc/suricata/suricata_39062_hn1/suricata.yaml
```

The configured log directory is:

```yaml
default-log-dir: /var/log/suricata/suricata_hn139062
```

The relevant EVE configuration is:

```yaml

    enabled: yes
    filetype: regular
    filename: eve.json
```

The V1 EVE output includes event types such as:

## IDS Validation with Nmap

A real scan was generated from the Ubuntu Docker host:

```text
Source: 10.10.10.10
Target: 10.10.10.1
```

Command:

```bash
sudo nmap -sS -sV -O -T4 10.10.10.1
```

Suricata detected:

```text
ET SCAN Possible Nmap User-Agent Observed
```

A corresponding EVE JSON event contained values such as:

```text
event_type: alert
src_ip: 10.10.10.10
dest_ip: 10.10.10.1
dest_port: 80
proto: TCP
signature_id: 2024364
```

This confirms that Suricata correctly detects reconnaissance activity on LAB-LAN.

## Forwarding EVE JSON to Wazuh

The Suricata EVE file is forwarded using syslog-ng.

The objective is to preserve the JSON payload exactly as generated by Suricata.

The forwarding pipeline is:

```text
Suricata
   |
   | eve.json
   v
syslog-ng on pfSense
   |
   | TCP 5514
   v
Wazuh Server
   |
   v
rsyslog
   |
   v
/var/log/suricata/eve.json
```

## syslog-ng Source

The source reads Suricata EVE files without parsing them:

```text
source s_suricata {
    wildcard-file(
        base-dir("/var/log/suricata")
        filename-pattern("*eve.json")
        recursive(yes)
        follow-freq(1)
        flags(no-parse)
    );
};
```

The important option is:

```text
flags(no-parse)
```

This prevents syslog-ng from interpreting the JSON as a regular syslog message.

## syslog-ng Destination

The Wazuh server receives the events on:

```text
10.10.10.20:5514/TCP
```

Destination:

```text
destination d_suricata_wazuh {
    network(
        "10.10.10.20"
        transport("tcp")
        port(5514)
        template("${MESSAGE}\n")
    );
};
```

Log path:

```text
log {
    source(s_suricata);
    destination(d_suricata_wazuh);
};
```

The template is used so the transmitted payload remains one JSON object per line.

## Non-Blocking Rule Parsing Warnings

During startup, a small number of PostgreSQL-related ET Open rules produced parsing errors because the required PostgreSQL detection support was not available in the active Suricata build/configuration.

These warnings did not prevent the IDS from operating.

Suricata still:

- started successfully;
- loaded thousands of other rules;
- monitored the LAN interface;
- generated EVE JSON events;
- detected the Nmap scan;
- forwarded the alert successfully to Wazuh.
